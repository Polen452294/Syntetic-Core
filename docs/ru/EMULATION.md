# Эмуляция устройств: данные, применение и ограничения

[English](../EMULATION.md) · Русская версия

## Четыре разных уровня

1. **Реальный хост:** Windows/Linux/macOS, архитектура CPU, физические устройства.
2. **Движок:** реальный Chromium, модифицированный Firefox/Camoufox или WebKit.
3. **Целевая конфигурация:** desktop/Android/iOS, модель, ОС и связанный рецепт.
4. **Наблюдаемые API:** значения, заданные движком, Playwright/CDP либо JS-слоем.

Выбор `target_os=macos` на Windows не запускает macOS. WebKit на Linux с iPhone
пресетом не становится настоящим Safari на физическом iPhone.

## Матрица

| Группа | Camoufox / Firefox | Chromium | WebKit / iOS |
|---|---|---|---|
| Целевая ОС | Нативный fingerprint Windows/macOS/Linux | UA/platform/Client Hints через CDP | Safari UA и iOS/iPadOS-пресет |
| Экран/viewport/DPR | Нативная конфигурация и проверка | Playwright/CDP | Playwright и мобильная геометрия |
| CPU | Согласованный нативный/JS CPU | CDP и согласованный JS/Workers | Наблюдаемый JS CPU по поддержке |
| GPU/WebGL | Каталог нативного движка | JS vendor/renderer WebGL1/2, включая поддержанный Worker OffscreenCanvas | JS vendor/renderer |
| Шрифты | Нативные наборы | JS-фильтрация FontFaceSet/canvas | Аналогичный JS-слой |
| Audio | Нативный seed, sample rate и buffer | Стабильный JS-шум при чтении API | При наличии Web Audio |
| Камеры/микрофоны/выходы | Нативные media-пресеты | Постоянные JS-списки с учётом разрешений | При наличии MediaDevices |
| Голоса | Нативные/library/local/none | Подмножество голосов хоста с согласованием языка/ОС | При наличии SpeechSynthesis |
| RAM | API не добавляется | `deviceMemory` в документе и WorkerNavigator | API не добавляется |
| Батарея | API не добавляется | Нативный BatteryManager с эмулируемыми значениями/событиями в документах | API не добавляется |
| Touch | Desktop без touch | Android maxTouchPoints=5, CDP + init-script | iOS platform/touch shim |
| Датчики | Документный JS при capability | Нативные CDP Android sensors либо JS fallback | Документный JS при capability |
| Тема/доступность | Штатные параметры | Штатные параметры | Штатные параметры |
| DNT/GPC | Нативно/проверенный fallback | Navigator + HTTP-заголовки | Navigator + HTTP-заголовки |

Таблица описывает перенесённую реализацию, а не результаты новой приёмки всех ОС.

## Согласованность рецепта

`coherence.version` и `recipe_id` связывают модель, ОС, движок, screen, viewport,
ориентацию, DPR, CPU, GPU и архитектуру Client Hints. Телефоны выбираются по точной
модели и `preset_id`; неизвестная модель не получает приблизительный запасной GPU.

Примеры правил исходной реализации:

- Apple M1/M2 Chromium: согласованный ARM рецепт и CPU 8.
- Android: браузерный контракт CPU 8 и multitouch 5; GPU задаётся отображением модели.
- iPhone/iPad mini 6: поддерживаемые браузерные CPU 4/6; iPad M1: 4/8.
- Camoufox: одно число CPU для нативного GPU sampler и JS; macOS-рецепты исключают 4.
- Экран × DPR ограничивает допустимый GPU-рецепт.
- Мобильный media-пресет не получает настольную USB-конференцию.
- Forced colors требует повышенного контраста.
- Синтетические координаты должны соответствовать timezone.

Целевые desktop ОС сохраняют исходные веса Windows/macOS/Linux 79/16/5 среди
доступных режимов. Это веса каталога, а не оценка рынка и не гарантия распределения
малой выборки. Количество пресетов можно получить из `phone_personas.PHONE_MODELS`
и `PHONE_PRESETS`; историческое число 1380 не используется как неизменный контракт.

## Постоянство и случайность

Один раз выбираются и сохраняются: fingerprint ID, рецепт, hardware значения,
медиа IDs, seed Canvas/audio, геометрия и нативная конфигурация. Временные паузы,
движения и отдельные поведенческие действия выбираются при выполнении.

`config_hash` контролирует persona. Отдельные identity-файлы закрепляют фактическую
конфигурацию браузерного слоя. Производные memory/battery для старого Chromium
профиля не переписывают persona, но сохраняются отдельно. Изменение seed/движка
существующего профиля отклоняется.

## Общая session policy

- Canvas 2D `fillText`/`strokeText`: постоянный сдвиг до ±0,02 px. Чтение пикселей
  остаётся нативным; разные seed не обязаны давать разные хеши любого рисунка.
- Proxy/WeakMap-слой задаёт зарегистрированным функциям и геттерам форму
  `[native code]`. Это JS-реализация, а не перевод функций в нативный код.
- `navigator.webdriver` должен быть строго `false`; Camoufox проверяется в основном мире.
- Chromium получает согласованные значения memory/battery даже при отсутствии
  явного `persona.emulation`.
- Инициализация выполняется до выдачи context; отсутствие обязательного слоя
  завершает подготовку ошибкой.

## Documents и Workers

Init scripts охватывают будущие документы, iframe и popup; существующие frames
обрабатываются при подготовке. Camoufox получает соответствующие скрипты в main
и isolated worlds.

В Chromium Workers отдельно передаются CPU, `deviceMemory`, UA/platform и WebGL.
Client Hints задаются CDP. Батарея, DOM permissions, шрифтовая фильтрация, документные
датчики и Canvas text shift в Worker-скрипт автоматически не включаются.
Нельзя выводить полноту Workers только из совпадения navigator в документе.

## Нативные особенности

Android поддерживает согласованные виртуальные датчики и периодическое движение;
foldable-пресеты — posture/сегменты внутреннего экрана. Частота motion — заданная
цель цикла, а не realtime-гарантия. CPU throttling замедляет исполнение, но не
моделирует конкретный процессор. Text scale может округляться движком.

WebKit перед JS проверяет WebAudio, MediaDevices, SpeechSynthesis и декодирование
WAV/H.264/AAC. Проверка выполняется локально. Linux требует GStreamer/codecs;
на Windows весь WebKit runtime запрещён политикой.

## Что не заменяется полностью

Физическая RAM, SIM/оператор, число USB-портов, реальная производительность CPU,
GPU-лимиты и полный набор расширений Chromium/WebKit, все CSS-метрики шрифтов,
реальные потоки камер/микрофонов и полный стек физической ОС.

`enumerateDevices` не создаёт видеопоток. Голоса могут отсутствовать. BrowserForge
сам по себе не применяется как отдельный инжектор окружения. TLS/HTTP fingerprints
принадлежат установленному браузеру; произвольной их рандомизации в persona нет.
HTTP `Device-Memory`/`Sec-CH-Device-Memory` отдельно не переопределяются.

Датчики требуют безопасного контекста, разрешённого origin и применимой Permissions
Policy. Геолокация выбирается около центра timezone; это не определение координат
IP. Согласование страны IP, timezone и языка остаётся задачей приложения/провайдера.

## Поведение

Перенесены посимвольный ввод, ограниченные логнормальные паузы, кривые движения,
прокрутка, tap-пути и UXActivityDispatcher. Desktop-движения не применяются к
телефону. `maintain_presence()` запускается явно и не нужен для DOM-парсинга.
Наличие синтетической активности не гарантирует учёт визита сторонней аналитикой.
